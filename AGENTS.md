# Agents

Documentation for agents working on this codebase.

## Project Overview

**StreamFile Server NodeJS** — A lightweight, cross-platform web server for file sharing, markdown viewing, and secure file management. No database required.

- **Monorepo**: pnpm workspace with two independent packages (`src/backend`, `src/frontend/markdown-viewer`)
- **Package Manager**: pnpm (enforced via `only-allow` preinstall hook)
- **TypeScript**: v7 (Go-based compiler, `^7.0.2`)

## Build Pipeline

```
pnpm build  →  uv run build.py  →  scripts/build/builder.py
```

The Python build script (`build.py`) runs four steps in order:

| Step               | Command                                                            | What it does                                                               |
| ------------------ | ------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| **1. Clean**       | Removes `dist/`, `public/markdown-viewer/`, `public/styles.css`    | Fresh start                                                                |
| **2. Backend**     | `node src/backend/build/bundle-backend.cjs` (esbuild)              | Bundles `server.ts` → `dist/server.js`                                     |
| **3. Frontend**    | `pnpm tsc && pnpm vite build` in `src/frontend/markdown-viewer/`   | Type-checks then builds React app → `src/frontend/public/markdown-viewer/` |
| **4. CSS**         | `pnpm postcss ./src/input.css -o ./src/frontend/public/styles.css` | Compiles Tailwind v4 → `public/styles.css`                                 |
| **5. Copy assets** | Copies `src/frontend/public/` → `dist/public/`                     | Packages everything for distribution                                       |

**Run the server** after build:

```bash
cd dist && node server.js
```

**Dev mode** (no build needed):

```bash
# Backend
cd src/backend && pnpm dev

# Frontend (separate dev server)
cd src/frontend/markdown-viewer && pnpm dev
```

## Toolchain

### Formatting — Prettier

```bash
pnpm format
```

Runs `prettier --write .` from the root. Config (`.prettierrc`):

- `semi: true`, `singleQuote: true`
- `tabWidth: 2`, `useTabs: false`
- `trailingComma: "all"`, `printWidth: 80`
- `arrowParens: "always"`, `endOfLine: "lf"`

### TypeScript

- Version: **7.0.2** (Go-based compiler)
- Target: **ES2024**, `module: esnext`, `moduleResolution: bundler`
- Both packages use path aliases (`@/*` → project root for backend; `@/src` for frontend)

### Backend — esbuild

The backend is bundled via a CJS esbuild wrapper script (`src/backend/build/bundle-backend.cjs`), outputting to `dist/server.js`. It is **not** a TypeScript-to-JS compile — it packages the TypeScript source directly for Node.js execution via `tsx watch` in dev or `node` in prod.

### Frontend — Vite + React

- Vite 8 with `@vitejs/plugin-react` (React 19)
- **Single-bundle output**: all JS inlined into `markdown-viewer.js`, all CSS into `markdown-viewer.css`
- Tailwind CSS v4 via `@tailwindcss/postcss` (PostCSS pipeline)
- Path aliases: `@` → `./src`, `@/types`, `@/utils`, `@/components`, `@/test`

### Linting

- Backend: ESLint 10 + `typescript-eslint` (flat config in `eslint.config.ts`)
- Frontend: none (no ESLint config in the markdown-viewer package)

## Key Architecture Decisions

### Content Injection (Markdown Viewer)

The React app does **not** fetch its own markdown content. Instead:

- **Dev mode**: content is injected via `window.markdownContent` in `main.tsx` at startup
- **Prod mode**: the backend serves `markdown-viewer/index.html` which embeds the content before sending; the React app waits for the `markdownContentLoaded` custom event

This avoids CORS and path-resolution issues since the server controls the file path.

### File Access Tiers

| Directory              | Visibility             | Access                                 |
| ---------------------- | ---------------------- | -------------------------------------- |
| `files/`               | ✅ Public              | Web interface + direct URL             |
| `files/private-files/` | ❌ Hidden from listing | Direct URL only                        |
| `files/incoming/`      | ❌ Not accessible      | Upload staging only; blocked by server |

### Path Aliases

Both packages use TypeScript path aliases. In the backend, `@/*` maps to `src/backend/*`. In the frontend markdown-viewer, `@/*` maps to `src/frontend/markdown-viewer/src/*`.

## Dependencies

### Root (`package.json`)

Dev-only tooling for formatting and CSS compilation: `prettier`, `tailwindcss`, `@tailwindcss/postcss`, `autoprefixer`, `postcss`, `postcss-cli`, `@tailwindcss/cli`

- `express` — HTTP server
- `multer` — File upload handling
- `js-yaml` — Config file parsing
- `fast-glob` — File search globbing
- `serve-index` — Directory listing

- `react`, `react-dom` — UI framework
- `react-markdown` — Markdown rendering
- `remark-gfm`, `remark-math` — Markdown plugins (tables, math)
- `rehype-katex`, `rehype-raw` — KaTeX math rendering
- `katex` — LaTeX typesetting
